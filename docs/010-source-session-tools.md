# Trusted Source session tools

Extension capability `SOURCE_TOOLS_API = 1` adds `SourceHost.registerSessionTools(namespace, factory)`. The factory receives the actual DSH agent and, for a worker, its ticket. It returns tools with Zod schemas and `execute(args, signal)`. Names must start with `namespace_`; `orchestrator` is reserved. Register only trusted installed code, never message-defined tools. The returned disposer revokes tools from every bound session; registration also covers already loaded sessions. Tools are local to the managed session, so the inherited work-tool allowlist cannot silently hide them. Worker lifecycle guards still reject work after the ticket ends. Unrelated sessions and subagents do not receive these tools.

An adapter must recheck its current identity, conversation scope, pause/mute and permissions at execution and retry. Bind destinations and file references to stored authorized messages, not model-supplied claims. Preserve file versions, report unread or unsupported content honestly, and use durable idempotency for outgoing transfers. Returning `{ image: ImageAttachmentRef, ...metadata }` adds a model-visible image to the existing tool renderer. Raw file bytes, credentials and base64 do not belong in prompts or logs.

There is no generic 100-word limit. Reply/acknowledgement schemas have a 20,000-character bound; the source enforces any additional provider limits. Standalone prompts encourage complete task outcomes and available attachment tools. Existing Feishu word policy remains source-specific. Saved business roles and the authenticated agent communication contract are unchanged.

Validation: runtime tests cover early/late registration, main/worker visibility, reserved names and disposal. Outbox tests deliver 450-word replies and acknowledgements unchanged through a custom source. The platform suite, typecheck and built-extension smoke are required; real host/model/transport acceptance belongs to each adapter deployment.
